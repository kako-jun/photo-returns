# PhotoReturns — 機能一覧

---

## 日時ベースのリネーム

写真・動画ファイルの撮影日時を読み取り、`年月日_時分秒` という統一フォーマットにリネームする。
ファイル名がバラバラでも、複数デバイスからの写真が混在していても、すべて同じルールで整理される。

日時の取得には複数の方法を用意しており、ファイルごとに優先するソースを選べる。

| 優先度 | 日時の取得元 | 特徴 |
|--------|------------|------|
| 1 | EXIFメタデータ（撮影日時） | 最も正確。カメラ・スマートフォンが記録 |
| 2 | ファイル名に含まれる日付 | リネーム済みや特定アプリからの書き出しに有効 |
| 3 | ファイルの作成日時 | EXIFがない場合の代替 |
| 4 | ファイルの更新日時 | 最終手段。動画ファイルに多い |

写真のデフォルトはEXIF、動画のデフォルトはファイル更新日時に設定されている（動画にはEXIFが含まれないことが多いため）。

---

## 日付階層への自動分類

リネーム後のファイルは、`年 / 年月 / 年月日` の3階層に自動的に振り分けられる。

```
出力フォルダ/
└── 2025/
    └── 2025-01/
        └── 2025-01-01/
            ├── 2025-01-01_12-00-00.jpg
            └── 2025-01-01_14-30-00.mp4
```

この構造はOSのファイルマネージャーで直感的にたどれる。PhotoReturns を経由しなくてもそのまま閲覧できる。

## 広範なファイル形式への対応

写真は主要な形式を広く網羅する。動画はメタデータ抽出ライブラリの制約により、QuickTime系の
コンテナに絞っている。

| 種別 | 対応形式 |
|------|----------|
| 写真 | JPG, PNG, GIF, BMP, HEIC, HEIF, AVIF, WebP, TIFF ほか計11形式 |
| 動画 | MP4, MOV, M4V, WebM 計4形式 |

動画のメタデータ抽出には `mp4` クレートを使っており、対応するのは QuickTime 系コンテナ
（MP4/MOV/M4V/WebM）のみ。AVI/MKV/WMV/FLV/3GP/MPG/MPEG は撮影日時などのメタデータを
読み取れないため、意図的にスキャン対象から除外している。

HEIC/HEIF/AVIF は iPhone など主要スマートフォンの既定形式であり、日時・向き・寸法などの
EXIF は他形式と同様に読み取れる。ただしサムネイル・拡大表示（ライトボックス）はOSのwebview
依存のため、環境によっては画像を表示できないことがある。表示できない場合はレイアウトを
崩さず、ファイル形式名を示すプレースホルダに切り替わる。

## システム生成物の自動除外

Android/Google フォトで写真を削除すると、実体は `DCIM` 配下に `.trashed-*` という
ファイルとして残ることがある。これをそのままスキャン・取り込むと、削除したはずの写真が
リネームされて永久アーカイブに復活してしまう。端末が生成するサムネイル（`.thumbnails`）や
メディアスキャン抑止マーカー（`.nomedia`）、macOS の AppleDouble（`._*`）・OS メタデータ
（`.DS_Store` / `Thumbs.db`）も同様にユーザーの写真ではない。

PhotoReturns はスキャンの入口でこれらを既定で除外する（拡張子判定・日付抽出・バースト検出より前）。

| 対象 | 判定 |
|------|------|
| Android/Google フォトの削除済み (`.trashed-*`) | ベース名の前方一致 |
| 端末生成サムネイル (`.thumbnails/`) | パス成分のいずれかが一致 |
| メディアスキャン抑止マーカー (`.nomedia`) | ベース名一致 |
| AppleDouble (`._*`) | ベース名の前方一致 |
| OS メタデータ (`.DS_Store` / `Thumbs.db`) | ベース名一致 |

※ メディアスキャン抑止マーカー (`.nomedia`) と OS メタデータは、そもそも拡張子が写真・動画で
ないため除外をOFFにしても取り込み対象（`media`）には元々含まれない。この2ルールは除外
ON/OFFで結果を左右せず、「システムが何を捨てたか」を見せる除外件数の表示にのみ影響する。

除外された件数はスキャン結果画面に「EXCLUDED: N」として表示され、押すとルール別の内訳と
サンプルパスを確認できる。CLI では `--include-system-artifacts` を指定すると、この除外を
無効化して従来どおりすべて取り込む。

## バースト撮影の自動検出

連続撮影（バースト）した写真群を自動的に識別する。
3秒以内に3枚以上撮影されたファイルを「バースト」と判定し、ファイル名に連番を付与する。

```
2025-01-01_12-00-01_01.jpg   ← バースト1枚目
2025-01-01_12-00-01_02.jpg   ← バースト2枚目
2025-01-01_12-00-01_03.jpg   ← バースト3枚目
```

同じ秒に複数のファイルが存在しても名前が衝突しない。

## 由来タグ（既定OFF）

複数のソース（Google Takeout / LINE 保存分 / 既存アーカイブ / 別端末など）から写真を1つの
ライブラリへ集約すると、通常の命名だけでは「どこから来たファイルか」が失われる。EXIF の
無い写真も多く、台帳ファイルに頼ると単独でコピー・移動した時点で由来が消えてしまう。
由来タグはファイル名自体に由来を残す機能。

### タグの決め方

1. **明示ラベル優先** — 設定パネルの「PROVENANCE TAG」欄にラベル（例 `takeout` /
   `line` / `pixel8`）を入力すると、スキャンする全ファイルにそのタグが使われる
2. **フォルダ由来フォールバック** — ラベルが空で「USE FOLDER NAME IF LABEL EMPTY」が
   ONのとき、ファイルの直上の親フォルダ名をタグとして使う。入力フォルダ直下のファイル
   （直上に親フォルダが無い）は入力フォルダ自身の名前を使う
3. どちらも無ければタグは付かない（**既定はこの状態**。出力は本機能導入前と1バイトも
   変わらない）

### タグの位置とファイル名

タグはバースト連番の後・衝突連番の前に付く。

| ケース | 出力例 |
|---|---|
| 通常 | `2025-04-22_20-59-15_takeout.jpg` |
| サブ秒 | `2025-04-22_20-59-15-250_takeout.jpg` |
| バースト | `2025-04-22_20-59-15_01_takeout.jpg` / `..._02_takeout.jpg` |
| 衝突 | `2025-04-22_20-59-15_takeout_01.jpg` |
| 日付なし（unsorted） | `<元のstem>_takeout.jpg` |

### サニタイズ

タグに使う文字列は決定的なルールでサニタイズされる。

- パス区切り・`\ / : * ? " < > |`・空白・`_` を `-` に置換
- 連続する `-` は1個に畳み、先頭末尾の `-` は除去。最大32文字で切り詰め
- 日本語などの非 ASCII 文字はそのまま保持
- サニタイズ後に空になったらタグなし扱い
- **2桁の純数字（`01` 等）は使えない**（バースト連番・衝突連番と見分けがつかないため）。
  全角数字（`０１` 等）や半角全角混在（`0１` 等）も同様に拒否する（機械的には区別できるが、
  人間が読むと `_01` と紛らわしいため）。明示ラベルでこれを指定するとスキャン自体が
  エラーになる。フォルダ名からの自動導出で該当した場合は警告ログを残してタグなしに
  フォールバックする

### CLI

Rust バックエンドのテスト用 CLI（`src-tauri/src/bin/cli.rs`、開発者向け）でも由来タグを
指定できる。対話形式に対応した一般ユーザー向けの「CLIモード」は今後の展望
（`docs/roadmap.md`「CLIモード」参照）。

```
cli <input_dir> <output_dir> --tag takeout            # 明示ラベル
cli <input_dir> <output_dir> --tag-from-folder         # フォルダ由来フォールバック
```

## EXIF回転のロスレス補正

スマートフォンで撮影した写真には、縦向き・横向きの情報がメタデータとして埋め込まれている。
PhotoReturns はこの情報を読み取り、画像を物理的に回転させた上で Orientation を 1 にリセットする。

JPEG は libjpeg-turbo の DCT 領域変換で**無劣化（ロスレス）**に回転し、撮影日時や GPS などの
EXIF はそのまま保持する。対応するのは回転（Orientation 1/3/6/8）のみで、現実のカメラ・スマホで
発生しないミラー系（2/4/5/7）は非対応としてスキップ・ログ記録する。

HEIC/HEIF/AVIF は EXIF の撮影日時・向き・寸法こそ読み取れるが、画像デコードライブラリが
非対応のためロスレス回転はできない。誤って壊れた画像を書き出す代わりに、事前に判定して
回転をスキップし、ログに記録する（他の写真情報は通常どおり整理される）。この判定は
グリッド側にも反映され、HEIC/HEIF/AVIF では Rotate 列のドロップダウンが「NO ROTATE (FMT)」
表示で無効化され、既定値も強制的に「回転なし」になる。After プレビューにも CSS 回転を
当てない。回らない実態に UI 側の見た目を合わせることで、「回ると表示されたのに待っても
回らない」という無言の不整合を防ぐ（#31）。

対応していないビューアーで見ても、正しい向きで表示される。
処理前後の見た目はグリッド上でも確認できる。

### 方向確認ポップアップ（眼科Cの4方向ピッカー）

EXIF の Orientation は「どれを人間に見せるか」の篩としてだけ使い、回転の正解は人間が決める。
スキャン後、回転候補（写真かつ Orientation≠1 かつ非ミラー かつロスレス回転に対応した形式）が
見つかると「向きを確認 (N)」ボタンが有効になる。HEIC/HEIF/AVIF はロスレス回転が非対応のため、
Orientation が付いていても候補には出てこない。押すと候補を1枚ずつポップアップ表示し、
EXIF 補正済みの見え方を初期表示する。

ユーザーは矢印キー（↑→↓←）またはクリックで「こっちが上」を1回指定するだけで即確定し、
自動的に次の写真へ進む（眼科の C 検査のように高速）。スペースキーで「何もせず次へ」（スキップ）、
Esc またはバツで途中終了できる。確定すると、その写真の回転モードを絶対角に設定するため、
あとは既存のロスレス回転がそのまま適用される。

なお既存の手動の回転ドロップダウンと Before/After プレビューはそのまま残る（Orientation=1 だが
実は横向き、といった取りこぼしを手動で拾える受け皿）。動画の向き補正は今後の対応予定。

## タイムゾーン補正

海外旅行中の写真は、端末のタイムゾーン設定によって撮影時刻がズレることがある。
オフセット値を手動で指定することで、正しい現地時刻に補正できる。

写真と動画で個別に設定できるため、混在するファイルでも柔軟に対応できる。

## ファイル名衝突時の連番付与

同じ出力先パス（同じ日付・同じバースト連番・同じ由来タグの組み合わせ）になるファイルが
複数ある場合、上書きはせず末尾に連番（`_01`, `_02`, `_03`, ...）を付与してすべて残す。

判定はファイル名の存在チェックのみで、ファイルの中身（ハッシュ値など）による重複検出は
行わない。そのため、同じ写真を含むフォルダを複数回処理すると、内容が同一でも別ファイルとして
複製される。

何度実行しても既存ファイルを上書き・破壊せず追記されるだけなので、失敗したファイルだけを
やり直す「Retry Failed Files」機能と組み合わせて安全に運用できる。内容ベースの重複検出は
将来の拡張候補（`docs/roadmap.md` 参照）。

## 並列処理による高速化

複数のファイルを同時に処理することで、大量のファイルでも短時間でスキャン・整理が完了する。
数百・数千枚の写真でも待ち時間を最小限に抑える。
